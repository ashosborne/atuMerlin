## Summary

Thirteen members are not hand-written source but **ARCAD-generated CL command snapshots**: the eight `QILESRVSRC/*.ILESRVPGM`, the two `QILESRC/*.ILEPGM`, `QBNDSRC/SAMPLE.BNDDIR`, `QMSGFSRC/SAMMSGF.MSGF` (the twelve build members of this slice) and `QDTASRC/LASTORDNO.DTAARA` (a data area — `ord-batch-ord900` / `ord-entry-ord100`, cited for its header only). Each carries the same three-line header — `Source generated by ARCAD Software` / `Using Direct Object FGRMON_OBJ/<name> of type <*TYPE>` (`FGRMON_DTA/LASTORDNO` for the data area) / `Time : 2022-05-17-14.54.NN.NNNNNN` — with timestamps spanning **four seconds** (14:54:17.006 → 14:54:21.181), i.e. one export run that read the *objects* in libraries `FGRMON_OBJ` (programs) and `FGRMON_DTA` (data) and wrote their create commands with `&O` / `&N` placeholders for library and name. They therefore describe the objects **as they were on 2022-05-17**, not a build recipe maintained since; the six `QSRVSRC/*.BND` binder sources are *not* generated (except `FPROVIDER.BND`, "Generated by ARCAD (signature by version *VERS)" — `c06`). The build itself is declared in `iproj.json` — `buildCommand: elias compile {branch}`, `objlib: &verlibatu`, `curlib: *CRTDFT`, `includePath: ATU_SRC/QPROTOSRC`, ARCAD extension `code ATU` / `libraryPrefix ATU` / `iasp *SYSBAS` / `validated true`, `repository git@github.com:AdrianAtArcad/atuMerlin.git` — and its only state file, `.elias/hashList.json`, records branch `FT_zel001` and a comparison hash per source path with `status: "DRY"`, nothing about compile options. Every option that decides binding, activation group, debug view, SQL commitment, date format, etc. and is not written in a member (`c05`, `c07`) is in ARCAD / elias, outside `ATU_SRC`. Treat all of this as metadata: it is not behaviour to carry, but it is the answer to "why does the tree not say how X is built".

## Inputs / outputs / observables

- In (to the generator, in 2022): the built objects in `FGRMON_OBJ`. Out: the twelve members. In (to elias, now): the source tree on a branch; out: objects in `&verlibatu` (a version library whose name is substituted per build).
- Observable: `DSPOBJD <obj> DETAIL(*SERVICE)` on the box shows the real create date and source member; comparing with 2022-05-17 tells whether the objects have been rebuilt since the snapshot (runtime-confirmable).

## Behaviour as implemented

1. **Object-to-source direction.** The header says "Using Direct Object …": the member was produced *from the object*, so it reflects the object's attributes at that moment (module list, export mode, activation group, binder list) — the same attributes `DSPSRVPGM` / `DSPPGM` would show. That is why they are trustworthy as *facts about the 2022 build* (`c04`, `c06`, `c07`, `c08`) and why the tree has no `CRTBNDRPG` / `CRTRPGMOD` / `CRTSQLRPGI` members: those objects were not exported this way. — headers
2. **One export run, ordered by type.** `*BNDDIR` (17.006) → `*DTAARA` (17.381) → `*PGM` (19.610, 19.700) → `*SRVPGM` (20.143 … 20.785, alphabetical) → `*MSGF` (21.181). No member from any other run exists; nothing was regenerated later. Programs and service programs came from `FGRMON_OBJ`, the data area from `FGRMON_DTA` — a two-library (object / data) layout on the source box. — the thirteen timestamps
3. **`&O` / `&N`** in every generated command (`SRVPGM(&O/&N)`, `PGM(&O/&N)`, `BNDDIR(&O/&N)`, `MSGF(&O/&N)`) are ARCAD substitution variables (object library, object name) resolved at build; the source never names a library for an object it creates. Referenced objects, by contrast, are unqualified (`MODULE(ART300 ART301)`, `BNDSRVPGM(FFAMILLY)`) or `*LIBL` (`SAMPLE.BNDDIR` entries, `SRCFILE(*LIBL/QSRVSRC)`) — everything resolves through the build job's library list. — `c01`, `c04`, `c06` lines
4. **`iproj.json`** is the IBM i project-mode descriptor: `objlib &verlibatu` (a variable — the version library), `curlib *CRTDFT`, `includePath` for the `/copy` member form (`c02`), and an `arcad` extension with the application code `ATU` and library prefix `ATU` (so `&verlibatu` is an `ATU…` library). `buildCommand` / `compileCommand` delegate everything to `elias`. No per-object, per-type or per-directory compile options appear. — `iproj.json`
5. **`.elias/hashList.json`** — `branch: FT_zel001`; for each of 138 source paths (all `ATU_SRC/**` members plus `iproj.json` and `README.md`) a `comparisonHash` and `status: "DRY"`; no timestamps, no options, no object names. It is elias's change-detection state for a dry run, committed to the repository. — `.elias/hashList.json`
6. **Two coding generations in the source itself** (context, not build): fixed-form `h` H-specs on nine `bnddir` programs vs free-form `ctl-opt` on three (`c03`); fixed-form P-specs throughout the modules; the `FPROVIDER` binder versioned by ARCAD vs five hand-fixed `'V1'` (`c06`); one RPG III member (`COU200.RPG`). The snapshot date (2022) post-dates all of it.
7. **`SAMMSGF.MSGF`** is the same kind of snapshot (`CRTMSGF MSGF(&O/&N) CCSID(65535)` followed by `ADDMSGD`s — `menu-cmd-shell-c05`, documented; cited here for the header only). — `SAMMSGF.MSGF:4-8`

## Edge cases found in code

- **The snapshot may be stale relative to the box.** Anything rebuilt after 2022-05-17 with different options (a new module in `FARTICLE` — the `ART302` question, `c03`; an `ACTGRP` change, `c07`) would not be reflected here. The tree offers no way to tell; `DSPOBJD` on the box does.
- **Binding for four programs has no generated member** (`c05`) — consistent with the export covering only `*BNDDIR`, `*PGM` created by `CRTPGM`, `*SRVPGM` and `*MSGF`; single-module `CRTBNDxxx` programs were not exported (their create commands are derived by elias from the file extension and `.PGM.` infix — `c04`).
- **`FFAMILLY.ILESRVPGM` `%TEXT` "Functions Country"** (`c06`) — the object text was wrong *on the box* in 2022 (the snapshot copies it), not a transcription error.
- **`hashList.json` is committed** — a tool state file in the repository; harmless, but it means every source edit shows twice in a diff (member + hash).
- **`repository` in `iproj.json` points at `AdrianAtArcad/atuMerlin`**, not this fork — provenance of the tree.
