## Summary

`SAMMSGF.MSGF` is an ARCAD-generated build script (`CRTMSGF` + 12 `ADDMSGD`, extracted 2022-05-17 from the object `FGRMON_OBJ/SAMMSGF`) that defines the application's message file: **12 ids** in four number bands — `ERR0001`–`ERR0005` ("<entity> unknown. Press F4 to select." for family, country, article, customer, provider), `ERR0103` ("Code &1 Unknown.", `&1 *CHAR 6`), `ERR1001` / `ERR1002` (delivered-vs-ordered quantity rules), `ERR2000` ("Customer &1 /Phone &2 Already Exist", `&1 *CHAR 30`, `&2 *CHAR 15`), `ERR2001` / `ERR2002` (phone mandatory / digits only). Every message is `SEV(0)`, has **no second-level text**, and is tagged `CCSID(297)` (EBCDIC France) inside a file created `CCSID(65535)` (no conversion). The messages are consumed **only by display files**, via `ERRMSGID(<id> *LIBL/SAMMSGF <indicator> [&ERRDATA])` on input fields — 12 sites in 9 DSPFs — never by RPG/COBOL/CL `SNDPGMMSG` or `QMHSNDPM`; the menu names the file as `submsgf=sammsgf` (`c08`) but uses none of the ids. Nine of the twelve are referenced (`c06` corrects Phase A's eight). The texts are therefore the exact user-visible validation strings for the entity-unknown, duplicate-customer, phone and quantity rules — a resource file for the target, not behaviour.

— `SAMMSGF.MSGF:9-32`; DSPF lines as cited

1. `CRTMSGF … CCSID(65535)`: the file itself declares no CCSID; each `ADDMSGD … CCSID(297)` tags its text as EBCDIC 297 (France) — the texts are English, the tag is the build box's job CCSID (inference). — `SAMMSGF.MSGF:8,10,12,…`
2. `SEV(0)` on every message: informational severity; irrelevant to `ERRMSGID` display (severity matters for `SNDPGMMSG` / break handling), so no consumer depends on it. — `SAMMSGF.MSGF:10-32`
3. `ERR0103` declares one substitution variable `*CHAR 6`; the three by-id screens supply `ERRDATA 6A P` (program-to-system field) — width matches. — `SAMMSGF.MSGF:19-20`, `PRO250D.DSPF:30-32`
4. `ERR2000` declares `*CHAR 30` + `*CHAR 15` = 45 bytes; `CUS200D` supplies `ERRDATA 45A P` — width matches (`CUSTNM` 30 + `CUPHONE` 15 by `REFFLD`). — `SAMMSGF.MSGF:27-28`, `CUS200D.DSPF:107-110`
5. Every consumer qualifies the file as `*LIBL/SAMMSGF` — run-time library-list resolution, same rule as the menu's unqualified `submsgf`. — all DSPF sites, `SAMMNU.MENU:5`

## Validation rules found in code

- The messages *voice* validation rules that live in the programs and DSPFs (indicator set by RPG/COBOL logic; e.g. `ART200:287` `errFamilly = *on` when `existArtFam(artifa)` fails → `*IN40` → `ERR0001`). This card records the text; the rules are the owning slices'. — `ATU_SRC/QRPGLESRC/ART200.PGM.SQLRPGLE:34,286-288`
- The `FMT` widths are the only contract the message file imposes on its callers (points 3–4 above); both match.

## Edge cases found in code

- **`ERR0001` misspells "Family" as `Familly`** — consistent with the source tree's own spelling (`FAMILLY.RPGLEINC`, `ART200D` constant `Familly. . . .`), so the screen is internally consistent; a target resource file should decide once. — `SAMMSGF.MSGF:10`, `ART200D.DSPF:93`, `ART200.PGM.SQLRPGLE:14`
- **`ERR1002` grammar** (`lower that`) — as-is. — `SAMMSGF.MSGF:25-26`
- **`ERR2000` text has a space before the slash** (`Customer &1 /Phone &2`) and `&1` is a 30-byte name blank-padded — the rendered line will show the padding before `/Phone`. As-is. — `SAMMSGF.MSGF:27`
- **Mixed literal / catalogue strategy in the same DSPFs:** `ART200D:90` `ERRMSG('A description is mandatory' 41)` and `CUS200D:106` `ERRMSG('The name is mandatory' 41)` are *literal* texts next to `ERRMSGID` catalogue references — mandatory-field messages were never put in `SAMMSGF`. Any "all messages come from the message file" assumption is false. — `ART200D.DSPF:90-91`, `CUS200D.DSPF:106`
- **No second-level text, no reply values, no `DMPLST`, no `LOGPRB`** — first-level text is the whole content. — `SAMMSGF.MSGF:9-32`
- **Number bands** (`00xx` entity-unknown, `01xx` generic by-id, `10xx` order quantity, `20xx` customer) are a convention visible in the ids only; nothing enforces or documents it. Inference.

## Dependencies

- Consumers: the nine DSPFs above (their slices own the rules); `SAMMNU` (`c08`, declaration only).
- Build: `&O/&N` substitution by the ARCAD build — outside the tree.

## Assumptions / unknowns

- Platform: `ERRMSGID` retrieves first-level text at display time from the named file on `*LIBL`; `CCSID(297)` tagging vs the display job's CCSID may cause character substitution for non-invariant characters — none of the twelve texts uses one (letters, digits, `.`, `/`, `&`), so no practical effect. Inference / runtime-confirmable.
- Target stance (room, prose only — `SME_BRIEF.md`): carry the **nine live** texts as a message / i18n resource keyed by id (the CUS vertical, converted under waiver, already reproduces the customer-rule texts inside its own validation — not checked or widened here); drop `ERR0003`–`ERR0005` (`c06`) or keep them as reserved ids — room decision.
